# FML 是什么

FML，即**全系统建模语言**（Full-System Modeling Language），是一种用 Rust
给整个系统写周期级模型的方式，并且并行地运行它们。一个模型可以是流水线的一级、一块 GPU，或者许多块 GPU 和它们之间的网络：有的部分由时钟驱动，有的部分由事件驱动，都在一个程序里。

## 思路

硬件里有许多事情同时发生，但并行运行它们的仿真器通常要付出两份代价：一份在正确性上，两个部分争用同一份状态的时候；一份在工作量上，建模的人得说明哪些可以并行，再手工同步。

FML 两样都不要求。每个 task 写成一个普通函数，参数是它碰到的状态；通过每个参数的类型说明，在一个周期之内，它与碰同一份状态的其他 task 谁先谁后：

```rust
fn issue(ctx: &mut fml::TaskCtx,
         scoreboard: &Scoreboard,          // 本周期开始时的值
         ready: &'latest Ready,            // 本周期的写者写过之后的值
         queue: &mut fml::FifoTx<Inst>)    // 这个 task 写它
```

只凭这些声明，FML 就推出模型里的全部顺序。顺序有歧义的模型会被拒绝；其余的被调度到所有核上，并且保证结果就是串行运行会得到的那个，不论用几个 worker。

## 模型由什么组成

- **模块**：带参数、状态、触发源和子模块的 Rust 结构体。子模块数组的大小可以由参数决定。
- **状态**：普通的 Rust 值、固定容量的容器、稀疏存储和外部对象。
- **触发源**：时钟，周期和相位都是以皮秒计的精确整数，时钟域的数量不限；以及事件，带一个载荷和一个延迟，延迟可以是物理时间，也可以是一个 delta 周期。
- **task**：由模块的触发源运行的 Rust 函数，读写模块的状态，发出事件。
- **组件与接口**：可复用的模块，比如 `Fifo`；别的模块通过有类型的接口访问它，接口同时也定下谁先动作。
- **外部端口**：宿主对象，比如 trace 读取器、功能模型或 RTL 仿真，供 task 调用。

## 能得到什么

- **每种配置下结果都相同。** 一个 worker 还是一百个，时刻点重叠还是一个一个地运行：最终状态、事件和结束方式都一样。
- **速度。** 模型在多个核上运行，没有全局锁，彼此独立的工作可以跑在其余工作的前面。GPGPU-Sim 复现在 8 个 worker 上跑 Accel-Sim 的基准，速度是 Accel-Sim 的
  11 到 18 倍。
- **快照**，在仿真运行的同时拍下，用来恢复运行、复现问题。
- **加载时报错**，覆盖大多数建模错误（一个寄存器有两个写者、引用没有连接、顺序成环），并用模型里的实例路径指明出错的位置。

## FML 适合什么

FML 是为这样一类系统的周期级模型而做的：各部分在已知的时刻通过状态和事件相互作用，比如处理器、加速器、存储层次、互连、网络。它不是硬件描述语言：模型用 Rust
描述每个周期的行为，而不是门和连线；需要那一层细节时，可以通过外部端口调用
RTL 仿真器。
